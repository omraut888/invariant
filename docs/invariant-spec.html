Technical Specification — v1.0

INVARIANT

An autonomous quant research pipeline that discovers candidate trading signals, proves they are causal rather than coincidental, sizes them into a portfolio that stays optimal under the worst plausible market regime, certifies that robustness adversarially, and writes the investment memo justifying — or killing — the strategy. No stage is a black box; every stage is independently falsifiable.

Codename: INVARIANT
Formerly: PROMETHEUS
Class: Closed-loop research system
Stages: 5
Reuses: Meridian (RAG) · Umbra (coverage diagnostics)

00 Positioning Statement

Most quant portfolio projects show a backtest. INVARIANT shows a research process — the thing a quant researcher actually does between "I have an idea" and "we're trading this." It does not optimize for the best-looking Sharpe ratio. It optimizes for survivability of belief under scrutiny: a signal only reaches the portfolio if it survives causal validation, information-decay estimation, distributionally robust construction, and adversarial stress — in that order, with each stage capable of killing the candidate outright.

The name, explained

An invariant is a property that holds true under transformation — the thing that doesn't change when everything around it does. That is precisely what Stage 4 tests for: does this signal's edge hold invariant across market regimes it has never seen, or does it only work in the one regime it was discovered in. The name is not decoration — it's the system's actual thesis.

01 The Problem

Three failure modes account for almost every dead quant strategy:

Failure modeWhat actually happenedStandard tooling's blind spot
Spurious signalA feature correlates with returns because both are driven by a third, unmodeled factor — not because the feature causes anything.Correlation scans and standard feature-importance methods can't distinguish cause from confound.
Silent decayA real signal gets arbitraged away by the market learning about it, and keeps being traded past its useful life.Static backtests report a Sharpe ratio, not a decay rate.
Regime blindnessA strategy is optimal against the one historical sample it was tuned on and breaks the first time a genuinely novel regime occurs.Historical backtesting can only replay what already happened, never what could.

INVARIANT is architected so each failure mode has a dedicated stage whose entire job is to kill candidates that would fail that way — before capital, or in this case a decision, is ever committed.

02 System Architecture

Feature Universe ──▶ Stage 1 · Causal Discovery ──▶ candidate signals (causally grounded) │ ▼ Stage 2 · Decay Validation ──▶ surviving signals + half-life estimate │ ▼ Stage 3 · DRO Portfolio Construction ──▶ candidate portfolio weights │ ▼ Stage 4 · Adversarial Certification ──▶ pass/fail + worst-case Sharpe distribution │ ▼ Stage 5 · Research Memo Generation ──▶ citation-backed investment memo (PDF)

Orchestration is a FastAPI service with each stage as an independently callable module and a Prefect (or Airflow) DAG tying them together, so any stage can be run, inspected, and re-run in isolation — this matters for the interview narrative as much as the engineering: you can open any single stage and defend it on its own.

03 Stage 1 — Causal Hypothesis Discovery

Standard alpha research scans a feature universe for correlation with forward returns. INVARIANT instead runs constraint-based and score-based causal discovery over the feature universe to recover a causal DAG, then keeps only candidate signals that are structurally upstream of returns in that graph — not merely associated with them.

Method
  • Run the PC algorithm (constraint-based, via causal-learn) for an interpretable, auditable graph on the full feature set (macro series, cross-asset factors, engineered technicals, alt-data proxies).
  • Cross-check with NOTEARS (continuous optimization, score-based) to catch nonlinear structure the PC algorithm's independence tests might miss.
  • A candidate signal survives Stage 1 only if it has a directed causal path into the returns node in both recovered graphs, or if it survives a targeted intervention test (do-calculus via dowhy): does the estimated causal effect remain significant when you simulate intervening on known confounders?
P(return | do(signal = s)) ≠ P(return | signal = s) → signal is confounded, discard P(return | do(signal = s)) ≈ P(return | signal = s) → signal survives Stage 1

This is the stage that kills the majority of naive "alpha discovery" candidates immediately — most features that look predictive in a correlation scan fail the intervention test because they're downstream of a shared macro factor, not causally linked to returns themselves.

04 Stage 2 — Information-Theoretic Decay Validation

A signal that survives Stage 1 is causally real, but real signals decay as the market learns about them. Stage 2 estimates the half-life of the edge using transfer entropy — a measure of directed information flow — computed over rolling windows.

TE(Signal → Return) = Σ p(r_t+1, r_t, s_t) · log[ p(r_t+1 | r_t, s_t) / p(r_t+1 | r_t) ]

Tracking this quantity over rolling 60/120/252-day windows produces a decay curve. Fitting an exponential decay model to that curve gives an explicit half-life estimate in trading days — turning "is this signal still good" from a gut call into a number with a confidence interval. A signal with a rapidly shrinking transfer-entropy curve is flagged as crowded/decaying even if its trailing Sharpe still looks fine, which is exactly the blind spot that catches most quant teams late.

05 Stage 3 — Distributionally Robust Portfolio Construction

Standard mean-variance optimization (Markowitz) assumes you know the true return distribution and optimizes against it directly — which is precisely why it's fragile: it's optimal for exactly one distributional assumption and can be badly wrong under any other. Stage 3 instead solves a distributionally robust optimization (DRO) problem: optimize for the worst case over an entire ball

min_w max_{Q ∈ B_ε(P̂)} E_Q[ −wᵀr ] where B_ε(P̂) = { Q : W(Q, P̂) ≤ ε } (Wasserstein ball of radius ε around empirical distribution P̂)

This is solved as a convex program via cvxpy using the dual reformulation of the Wasserstein DRO problem (Blanchet & Murthy / Esfahani & Kuhn formulations) — tractable in practice, and it is an active current research area in quantitative portfolio theory, not textbook material. The radius ε is itself a tunable "how paranoid should the portfolio be" dial, which becomes a genuinely interesting design decision to walk an interviewer through.

06 Stage 4 — Adversarial Regime Certification

This is the module you already scoped as a standalone project — here it's the certification gate before anything is called a "strategy." An RL adversary is trained to actively search for the market path that minimizes the candidate portfolio's Sharpe ratio, subject to a hard constraint that the generated path remains statistically indistinguishable from real historical regimes.

Formulation
  • Generator: a regime-conditional diffusion model, conditioned on a latent regime variable inferred via a Hidden Markov Model fit on historical returns, produces candidate synthetic price paths.
  • Adversary: a PPO agent (Stable-Baselines3) perturbs the regime-transition and volatility parameters of the generator to minimize the portfolio's realized Sharpe/Sortino on the resulting synthetic path.
  • Realism constraint: a Maximum Mean Discrepancy (MMD) penalty (or a GAN-style discriminator) blocks the adversary from cheating with statistically implausible paths — the adversary can only win by finding a real-looking regime the portfolio is fragile to, not an invented one.

The output isn't a single "certified/not certified" flag — it's a full distribution of worst-case Sharpe outcomes with bootstrap confidence intervals, plus a Generalized Pareto Distribution fit to the tail for a proper extreme-value estimate of just how bad the worst case could get.

07 Stage 5 — Autonomous Research Memo Generation

This is where your existing RAG infrastructure (Meridian) plugs in directly rather than being rebuilt. For every strategy that survives Stages 1–4, an LLM agent retrieves supporting and contradicting evidence from academic literature (arXiv quant-finance categories, SSRN abstracts) via the same hybrid retrieval pipeline you built for Meridian, and drafts a structured investment-committee-style memo:

  • Causal graph summary and confounders ruled out (from Stage 1)
  • Estimated signal half-life and crowding risk (from Stage 2)
  • Portfolio construction rationale and chosen robustness radius (from Stage 3)
  • Worst-case certified performance under adversarial regimes, with citations to academic literature on similar factor/strategy classes, and an explicit statement of what would have to be true for this recommendation to be wrong

The memo is generated with inline citations back to retrieved sources — reusing Umbra's coverage-diagnostic logic to flag when the memo is making a claim the retrieval corpus doesn't actually support, so the system doesn't hallucinate justification for a strategy it should be more uncertain about.

09 Build Phases

Phase 1
Data + causal discovery core. Build the feature universe pipeline and get PC/NOTEARS running end to end on a fixed historical dataset. Deliverable: a causal graph you can visualize and defend for at least 3 real signal candidates.
Phase 2
Decay module + DRO construction. Transfer-entropy decay curves feeding into the Wasserstein DRO optimizer. Deliverable: portfolio weights for surviving signals with an explicit robustness radius chosen and justified.
Phase 3
Adversarial certification. This is the heaviest lift — diffusion generator + PPO adversary + MMD realism gate. Build the generator first and validate it against real historical regimes before adding the adversary.
Phase 4
Memo generation + orchestration. Wire Meridian's retrieval stack in, add citation-coverage checking from Umbra, and tie all four stages into one Prefect DAG behind a FastAPI endpoint.
Phase 5
Validation pass. Run the whole pipeline on out-of-sample data it has never touched — a strict walk-forward split — and document exactly which candidate signals it correctly killed and why. This is the section of the README that matters most in an interview.

10 Defending It In An Interview

The question you will get

"How do you know this isn't just an elaborate curve-fitting exercise?" Answer with the architecture, not adjectives: every stage has an explicit falsification criterion (failed intervention test, insufficient half-life, DRO-infeasible, failed adversarial certification), and Stage 5's memo states outright what evidence would change the recommendation. The system is designed to kill its own candidates at every stage — that's the credible answer, not a claim that the outputs are always right.

Practice walking through one real signal end to end, live, from raw feature to memo, including at least one candidate that INVARIANT correctly rejected and why. A system that only ever shows you its winners is a red flag to a quant interviewer; a system that can show you what it killed and the exact stage that killed it is the whole pitch.
